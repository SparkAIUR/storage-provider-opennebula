## Required corrections before tagging

1. Automatic local-device recovery must not detach a metadata-attached disk without a node/controller no-mount handoff. A final GET or report CAS does not eliminate the mount/detach race. Use the conservative fail-closed fallback in this release, with an actionable manual-repair outcome; keep safe metadata-absent attachment recovery. No operator force flag may silently authorize an unsafe detach. Node confirmation and deletion must be conditional on the observed episode on every conflict retry. Distinguish a hotplug operation in progress from attachment completion that can be confirmed. Test the episode-commit/mount boundary and stale confirmation retries.
2. Reconstruct all provably owned CephFS binds before recording a missing session or remounting, including absent stage and disconnected binds from an older superblock. Check adjacent kubelet metadata, ambiguity, mount identities and other volume stages. Fail closed when ownership is uncertain. Apply to both NodeStage and NodePublish. Test two sibling targets, read-only flags, and an unrelated volume.
3. Snapshot persistence must not hold a global mutex across Kubernetes I/O or block hotplug admission/cancellation. Preserve successful-write caching and per-node ordering, use bounded API contexts, and retry failed final clearing without allowing an older delayed active snapshot to replace completion. Test blocked node A while node B dispatches/cancels, failed writes and completion/debounce ordering.
4. Successful staging and controller repair guards must read current durable repair state instead of independent stale caches. Make timeout-derived repair publication and cleanup episode-bound and recoverable across the report/repair-record commit boundary. Test late confirmation and a failed repair write.
5. Forced local-disk reprobe must resolve current recovery-mode annotations and deadline before any cleanup. Historical session RecoveryMode cannot authorize a bypass. Fail closed when current state cannot be verified; test setting, removal and expiry.
6. A benchmark must not fail its own admission check after adding its expected attachment. Gate before run creation, including recovery after controller restart; test seven healthy attachments followed by its eighth and normal result collection.

Oracle's failed-confirmation-cleanup finding was already corrected by the confirmed-report reset added in `e34b887` after its snapshot. Reconcile that change and verify the fresh-episode regression rather than duplicating the fix.

The corrected expansion byte comparison is sound. Clarify that statfs byte capacity is diagnostic while a statfs syscall failure remains fatal, or deliberately make syscall errors diagnostic and test that contract.
